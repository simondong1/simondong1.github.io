Understanding Flash Attention The same math, without the score matrix

Flash Attention is not a new attention formula. It is a way to run the usual softmax attention so the big query-by-key score matrix never lands in GPU memory.

Simon Dong•August 2026•Kernels

Every modern softmax transformer still computes the same thing: compare queries to keys, turn those scores into weights, mix the values. Flash Attention changes only where those scores live. They exist for the length of one tile, in registers, then they are gone.

Where this kernel is used

Flash Attention (FA2 / FA3 / FA4) is the default softmax-attention kernel behind PyTorch SDPA, vLLM, and SGLang for models that still do grouped-query attention — Qwen3, Llama, Gemma, and the GQA layers of hybrid models. It does not run linear attention (KDA, Mamba, GDN). Those replace the growing key/value list with a fixed state and use a different kernel family.

1.What the kernel computes

Start from one attention head and a short sequence. Each token has already been projected into a query, a key, and a value. Flash Attention does not do those projections. It takes the three tensors and returns the mixed output.

Q queries K keys V values O output

For each query token, the head does three things:

  1. Dot that query with every key. That produces one score per key token.
  2. Turn the scores into weights that sum to one (softmax).
  3. Mix the values with those weights. That mix is the output for this query.

This is the same rule as the 2017 transformer. If \(q\) is one query, \(k_j\) and \(v_j\) are the key and value at position \(j\), and \(\text{scale}\) is usually \(1/\sqrt{d}\):

One query, many keys
\[ \mathrm{score}_j = \mathrm{scale}\cdot q\cdot k_j,\qquad w_j = \frac{e^{\mathrm{score}_j}}{\sum_i e^{\mathrm{score}_i}},\qquad o = \sum_j w_j\, v_j \]

Causal decoding adds one extra rule: a query at position \(t\) may only use keys \(0\ldots t\). Sliding-window and ALiBi change which scores are allowed, or add a bias, before the same softmax. MLA is still this formula with a different width for keys versus values. Linear attention is not this formula.

Smallest useful example — what object we are building

Problem: one query, four keys. We want the weighted mix of four values. This is the baseline — the math Flash Attention must match, not yet the kernel.

Already-scaled scores \(\mathrm{score} = [1,\ 3,\ 0,\ 2]\). Values (one channel) \(v = [10,\ 20,\ 30,\ 40]\).

The largest score is \(3\). Softmax subtracts that max first so the exponentials stay finite:

\[ e^{\mathrm{score}-\,3} = [e^{-2},\ 1,\ e^{-3},\ e^{-1}] \approx [0.135,\ 1,\ 0.050,\ 0.368] \]

Those four numbers sum to about \(1.553\). Divide, then mix:

\[ o \approx \frac{0.135\cdot 10 + 1\cdot 20 + 0.050\cdot 30 + 0.368\cdot 40}{1.553} \approx 24.2 \]
The output is one number per channel, not a four-by-four matrix. The four scores were only a temporary tool to get the weights.

The naive implementation writes every score into a matrix \(S\) of shape (number of queries) × (number of keys), softmaxes the whole row, then multiplies by \(V\). That \(S\) is the object Flash Attention refuses to store.

2.Tiles, memory, and online softmax

Why the score matrix is the problem

Queries and keys grow with sequence length. Their outer product grows with length squared. For one Qwen3-8B layer, batch 1, 2,048 tokens, 32 query heads, float32 scores:

\[ 2048 \times 2048 \times 32 \times 4\ \mathrm{bytes} = 512\ \mathrm{MB} \]

That is only the temporary scores for one layer, written and read once. The model has 36 layers. Flash Attention’s claim is not a new formula. It is: never allocate that matrix.

The loop

Cut the query axis into tiles of height \(M\) and the key axis into tiles of width \(N\). One thread block owns one query tile. It keeps that query tile in fast memory, then walks key/value tiles from left to right.

Online softmax — same example, two tiles

Problem this calculation solves: show that the \(24.2\) from section 1 can be obtained without holding all four scores at once. Object we are building: a running triple (max, sum of exp, weighted values). This is the Flash Attention mechanism, on four numbers.

Tile 1 · keys 0 and 1 · scores 1, 3 · values 10, 20

Local max \(m_1 = 3\). Local exp-sum \(\ell_1 = e^{-2} + 1 \approx 1.135\). Local mix \(O_1 = e^{-2}\cdot 10 + 1\cdot 20 \approx 21.35\).

Tile 2 · keys 2 and 3 · scores 0, 2 · values 30, 40

New max is still \(3\). The first tile does not need rescaling. Local exp-sum \(\ell_2 = e^{-3} + e^{-1} \approx 0.418\). Local mix \(O_2 \approx 16.21\).

Merge is addition, because the max did not move:

\[ \ell = \ell_1 + \ell_2 \approx 1.553,\qquad O = O_1 + O_2 \approx 37.56,\qquad o = O / \ell \approx 24.2 \]

If the second tile had beaten the max, Flash Attention would rescale the old sum and the old mix by \(e^{m_{\mathrm{old}} - m_{\mathrm{new}}}\) first, then add. That is the identity that lets a later tile correct an earlier one. The combine step of split-KV (long decode, many thread blocks on one row) uses the same identity.

Running state after every key tile
\[ m \leftarrow \max(m, m_{\mathrm{tile}}),\quad \ell \leftarrow e^{m_{\mathrm{old}}-m}\,\ell + \ell_{\mathrm{tile}},\quad O \leftarrow e^{m_{\mathrm{old}}-m}\,O + O_{\mathrm{tile}} \]

Nothing in that triple grows with sequence length except the number of loop iterations. The score tile’s size is fixed: \(M \times N\) floats, split across the threads of one block, then overwritten.

Same loop, three GPU generations

Dao-lab Flash Attention 4 (CuTe, current fa4-v4.0.0.beta10) dispatches on compute capability. The walk above does not change. The unit that multiplies the tiles does.

GPUFA pathWho multiplies the tileTypical tile (head dim 128)
Ampere SM80 FA2 / FA4-cute SM80 Warp mma.sync, 4 warps, 128 threads 128 × 64
Hopper SM90 FA3 C++, or FA4-cute SM90 Warpgroup WGMMA; TMA can load contiguous K/V 128 × 128
Blackwell datacenter SM100 FA4 UMMA UMMA into tensor memory (TMEM) 128 × 128, optional 2-CTA
Blackwell GeForce / RTX PRO SM120 FA4-cute as SM80 Same mma.sync as Ampere; 99 KB shared memory 128 × 64 (128 × 128 would starve occupancy)

FA4-cute is the CuTe-DSL rewrite of that same loop (pip install flash-attn-4). It is not automatically faster than FA3. On Hopper, FA3 is the mature C++ kernel in hopper/; vLLM still prefers it on SM90 and only falls through to FA4 for shapes FA3 cannot run. On B200, FA3 does not exist — FA4’s SM100 UMMA path is the Dao-lab kernel. On SM120, FA4-cute subclasses the Ampere SM80 kernel and only changes the shared-memory budget. vLLM’s FA4 gate is SM90 / SM100 / SM110, not SM120.

So “running FA on Blackwell” is ambiguous until you name the chip. B200 (SM100) is a new MMA unit. RTX PRO 6000 (SM120) is Flash Attention’s Ampere loop on a Blackwell memory system.

3.Next: Qwen3-8B on B200

A later note will take the released Qwen3-8B shapes — 32 query heads, 8 KV heads, head dim 128, 36 layers — and time the same tensors through a materializing softmax and through Flash Attention on B200 (SM100). Sections 1–2 do not depend on that measurement.

Mental model so far

Softmax attention is scores, then weights, then a mix of values. Flash Attention computes that per key-tile, keeps only a running max, a running sum, and a running output, and overwrites the scores. Hopper and SM100 buy a faster multiplier for the same loop. SM120 runs the Ampere version of that loop.
